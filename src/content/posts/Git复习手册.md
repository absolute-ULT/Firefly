## 一、Git 是什么？

Git 是一个**版本管理工具**，给文件夹里的内容拍"快照"（commit），记录每一次改动。好处：

- 随时回到任何一次改动的状态（存档/读档）
- 看每次改了什么、谁改的、为什么改
- 放心大胆改代码，改坏了随时还原

### 核心：三个区域

```
工作区（你正在编辑的文件）
   │  git add          ← 把改动放进"购物车"
   ▼
暂存区（已挑选、准备提交的内容）
   │  git commit       ← 正式存档成一个版本
   ▼
版本库（.git 文件夹，历史永久存档）
```

关键理解：
- **工作区** = 硬盘上真实看到的文件
- **暂存区** = 购物车，只放你想保存的改动
- **版本库** = 每次 commit 后的历史快照
- `.git` 文件夹就是版本库实体，删掉它 = 全部历史丢失

## 二、命令速查表

### 1. 基础四步循环（最高频）

| 用途 | 命令 | 输出/效果 |
|---|---|---|
| 初始化仓库 | `git init` | 创建 `.git` 文件夹 |
| 查看状态 | `git status` | 显示文件在哪个区 |
| 查看具体改动行 | `git diff` | `+`新增 / `-`删除 |
| 加入暂存区 | `git add 文件名` | 静默成功（无输出=成功） |
| 存入历史 | `git commit -m "说明"` | 生成提交 + hash |
| 查看历史 | `git log` | 完整格式 |
| 精简历史 | `git log --oneline` | 每提交一行 |
| 图形历史 | `git log --oneline --graph` | 画出分支图 |

**提交信息是写给未来自己看的**，要写清"做了什么"，别写"改了一下"。

### 2. 状态单词对照表（git status 的输出）

| 显示 | 含义 |
|---|---|
| `Untracked files` | 新文件，Git 还不认识（??） |
| `Changes to be committed` | 已在暂存区待提交（A/M） |
| `nothing to commit, working tree clean` | 全部干净，无改动 |
| `Unmerged paths` | 有冲突待解决 |

### 3. 撤销三兄弟

| 场景 | 命令 |
|---|---|
| 放弃**工作区**未暂存的改动 | `git restore 文件名` |
| 把已 add 的文件**移出暂存区**（文件保留） | `git restore --staged 文件名` |
| 修改**上一次提交**的说明 | `git commit --amend` |
| ⚠️ 穿越回任意历史版本（会丢东西，慎用） | `git reset` |

> `--amend` 会生成**新的提交号**（hash 会变），因为本质是新提交替换旧提交。

### 4. 分支全家桶

| 用途 | 命令 |
|---|---|
| 查看分支 | `git branch`（`*` = 当前所在） |
| 创建并切换 | `git switch -c 分支名` |
| 切换分支 | `git switch 分支名` |
| 合并到当前分支 | `git merge 分支名` |
| 删除已合并分支 | `git branch -d 分支名`（安全，会检查） |
| 强制删除分支 | `git branch -D 分支名`（危险，不检查） |
| 查看已合并进 master 的分支 | `git branch --merged master` |

**分支是什么**：一份独立的"平行世界"，各改各的互不干扰，写好后 merge 回主干。

**两种合并结果**：
- `Fast-forward`：主干没动过，指针直接快进，无合并记录
- `ort` 策略生成合并提交：两边都动过，真正融合（合并提交有**两个父提交**）

### 5. 冲突处理（别怕，很简单）

冲突 = 两个分支**改了同一行**，Git 不知道听谁的。

文件里会出现：

```
<<<<<<< HEAD          ← 当前分支(master)的内容
（master 版本）
=======               ← 分割线
（feature 版本）
>>>>>>> feature       ← 被合并分支的内容
```

**解决 4 步**：
1. 打开冲突文件
2. 删掉三行标记（`<<<<<<<`、`=======`、`>>>>>>>`）
3. 手动整合成想要的内容
4. `git add 文件` → `git commit`（标记已解决并完成合并）

> 想反悔整个合并？`git merge --abort` 回到合并前。

### 6. .gitignore（防泄密黑名单）

把不想提交的文件写进去，Git 直接无视：

```
# 忽略所有 .env 文件（防止密码泄露）
*.env

.DS_Store
Thumbs.db
temp/
```

**安全习惯**：密码、密钥、本地配置永远不提交；`git status --ignored` 可查看被忽略文件。

## 三、标准工作流（背下来）

```
日常小改动：
  改代码 → git status 看状态 → git diff 看细节
        → git add → git commit -m "说明" → git log 回顾

开新功能：
  git switch -c feature-新功能     # 从主干拉出分支
  改改改 → add → commit            # 在分支上反复提交
  git switch master                # 回主干
  git merge feature-新功能          # 合并回来
  git branch -d feature-新功能      # 清理战场
```

## 四、八道测验题（附答案解析）

**Q1. 把修改放入暂存区用哪条命令？**
✅ `git add 文件名`
（购物车 = 暂存区；commit 是把购物车正式存档）

**Q2. 想"具体看改了哪几行"（+ 新增 / - 删除），用哪个？**
✅ `git diff`
🔍 **易错点**：`git status` 是"体检报告"——只说**哪些文件**变了（文件级）；`git diff` 是"病历明细"——说**每行**怎么变的（行级）。

**Q3. 精简版历史（一行一提交）？**
✅ `git log --oneline`

**Q4. 文件改坏还没 add，想回到上次提交的样子？**
✅ `git restore 文件名`（撤销工作区改动）

**Q5. 不小心 add 错文件，想移出暂存区？**
✅ `git restore --staged 文件名`（文件保留在硬盘）

**Q6. 创建并切换新分支的一条命令？**
✅ `git switch -c feature`（-c = create）
（`git branch feature` 只创建不切换）

**Q7. 冲突标记中 `<<<<<<< HEAD` 到 `=======` 的上半段代表？**
✅ 当前所在分支（HEAD）的内容
（下半段是"被合并分支"的内容；最终要手动决定保留哪些、删掉标记）

**Q8. `-d` 和 `-D` 区别？**
✅ `-d` 先检查是否已合并，未合并**拒绝删除**（安全）；`-D` 强制删除不管死活。
